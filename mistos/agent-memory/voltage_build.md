Officially maintained alongside Mist-OS as of 2026-09-18. Tree `~/voltage` (VoltageOS manifest branch `17`,
LineageOS lineage-24.0 device trees, stock CP2A kernel prebuilts copied from `~/mistos/device/google/shusky-kernels`).
Build: `bash ~/voltage_build_supervisor.sh 96 <dev> voltage_<dev>-cp2a-userdebug bacon` (installclean on attempt 1;
shiba 28 min clean, husky 9 min incremental with RBE).

**Load-bearing knowledge:**
- Signing keys are NOT in git. Generated by `vendor/voltage-priv/keys/keys.sh` (90 keys; the script exits non-zero
  even on success — check `ls *.pk8 | wc -l` = 90). Current set backed up at `~/voltage-keys-20260918.tar.gz`.
  A key change means every user must clean-flash; there is no OTA across it.
- The GApps "no space" bug: `device/google/zuma/BoardConfig-common.mk` only includes
  `vendor/lineage/config/BoardConfigReservedSize.mk`, absent in a Voltage tree, so images build exact-fit.
  Voltage ships its own identical file — just add the `-include vendor/voltage/config/BoardConfigReservedSize.mk`.
- Validate sepolicy with `m selinux_policy` BEFORE a full build; a vendor type cannot be referenced from
  system_ext private policy (and vice versa).
- Working assumption for this ROM: **users flash GApps afterwards**, so the Pixel Google blobs (ASI, AICore,
  Astrea, Hotword, Now Playing, PixelCameraServices) stay in, even though they idle in failure loops without GMS.
- Publishing: SourceForge `chiranz/voltage/{shiba,husky}/` + `img/` (boot, init_boot, vendor_boot,
  vendor_kernel_boot, dtbo). Deleting old remote zips needs the user — the sandbox blocks remote rm.

**Open:** recovery hangs on the Google logo (images verified complete; needs on-device data — see
voltage/VOLTAGE.md §7), eSIM unverified with GApps, PowerStats HAL missing from VINTF.
Docs: github.com/chiranz07/customrom `voltage/` (VOLTAGE.md, CHANGELOG.md, patches/). See [[customrom_server_state]].

**2026-09-18 update.** The reported recovery failure was **tester error — recovery works**; don't
re-investigate (VOLTAGE.md §7 keeps the record of what was verified). My earlier "PowerStats HAL not
declared in VINTF" claim was **wrong** — the AIDL HAL is declared by the blobs; corrected in the docs.
Found and fixed: Voltage ships Megvii/Sense `FaceUnlock` + `ro.face.sense_service=true`, the same hijack
Mist had, so face unlock was the software one; fix is `TARGET_FACE_UNLOCK_SUPPORTED := false` in
`voltage_{shiba,husky}.mk` **plus** re-copying the face feature XML the same upstream block would have
installed. **User decision: do NOT bundle GrapheneOS's Apps store** even though GmsCompat expects it —
link users to GrapheneOS's releases instead, out of respect for their stance. Open, unconfirmed: 409
`libperfmgr … in JSON config` lines that Mist doesn't produce; that string isn't in ROM source, so treat
it as a question, not a bug.
